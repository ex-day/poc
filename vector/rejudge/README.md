# AI の再判定と人の判定の一致（Issue [#12](https://github.com/ex-day/poc/issues/12)）

[#9](https://github.com/ex-day/poc/issues/9) で決めた構成は「ベクトルで候補を拾い、AI で再判定し、提案として出す」。本フォルダでは、このうち AI の再判定が人の判定とどこまで一致するかを測る。

## 中身

| ファイル | 役割 |
|---|---|
| `build_pairs.py` | #9 で人が関連度を付けた100件から、AI に渡す組（問い × 記事の題名・冒頭）を作り、`data/pairs.jsonl` に書く。**人の判定・仮判定は入れない** |
| `prompts/sent/` | **条件ごとに、サブエージェントに実際に渡した指示の全文**（入出力のファイル、守ること、判定の指示）。`intents.md` は問いごとの意図を書かせた指示 |
| `results/pairs_index.jsonl` | pair_id と、問いID・記事ID の対応（判定したときの対応を固定したもの）。`score.py` はこれで人の判定と照合する |
| `prompts/base.md` | 判定の指示（関連度 0〜3 の意味、理由の種類、出力の形） |
| `prompts/context.md` | 「前提あり」のときに足す、サービスの説明。あわせて問いごとの意図（`results/intents.jsonl`）を組に足す |
| `results/intents.jsonl` | 問いごとの意図。問いの文章とサービスの説明だけを見た別のサブエージェントが書いたもの（候補・判定は見せていない） |
| `prompts/criteria.md` | 「基準あり」のときに足す、人の判断基準（`../accuracy/README.md` の「関連度の付け方」を、#9 の100件の具体例を除いて書き直したもの） |
| `fetch_long.py` | 候補の記事の本文の先頭から最大1,000字を取り、`data/pairs_long.jsonl` を作る（Mac 等、Wikipedia に接続できる環境で） |
| `results/judge_*.jsonl` | AI の判定（関連度・理由の種類・理由） |
| `score.py` | 人の判定との一致を数え、`results/score.md` を書く |
| `data/` | 組（記事の冒頭を含むため、リポジトリには入れない） |

## やり方

- 判定役は、人の判定を見せないサブエージェント（Claude Code のサブエージェント。API の契約前のため、#2 と同じく Claude が判定役をする）。入力ファイル以外を読まないように指示した。
- 条件：Haiku・Sonnet × 基準なし・基準あり の4通りと、Sonnet・基準ありに次を足した3通り。各100件を1回ずつ。
  - 前提：サービスの説明と問いごとの意図
  - 記憶で補う：記事にないことも知っていれば補ってよい、と明示し、補ったら何を補ったかを knowledge に書かせる

**記憶の扱いについての注意**：「記憶で補う」以外の条件でも、指示（`prompts/sent/`）には「自分の知識と入力の文章だけで判定する」と書いており、モデルの知識を使うことは禁じていなかった。そのため「記憶で補う」は、記憶の利用を新たに許した条件ではなく、**記事にないことを補うよう明示し、補った内容を書かせた**条件として読む。記事の文章だけを根拠にさせた条件（記憶を禁じた条件）は試していない。
  - 長い本文：記事の冒頭300字の代わりに、本文の先頭から最大1,000字（`fetch_long.py`）
- 比べる相手：人の判定（`../accuracy/results/review_ruri-v3-30m.csv` の「判定（0〜3）」）。

```bash
cd vector/rejudge
python build_pairs.py      # ../accuracy/data/wikipedia_kanto.jsonl が必要（../accuracy/fetch_wikipedia.py）
# AI の判定（results/judge_*.jsonl）を作る（サブエージェント、または API で）
python score.py
```

## 結果

| 判定 | κ（4段階） | 重み付きκ | κ（3区分） | 正反対 |
|---|---|---|---|---|
| Sonnet・基準なし | 0.44 | 0.83 | 0.59 | 0 |
| Sonnet・基準あり | 0.54 | 0.86 | 0.67 | 0 |
| Sonnet・基準あり＋前提 | 0.52 | 0.81 | 0.58 | 0 |
| Sonnet・基準あり＋記憶で補う | 0.56 | 0.85 | 0.63 | 0 |
| Sonnet・基準あり＋長い本文 | 0.57 | 0.85 | 0.69 | 1 |

（Haiku と、Claude の仮判定を含む全体は score.md）

[results/score.md](results/score.md) を参照。考察は Issue #12 に残す。

### 読むときの注意

- 人の判定は、Claude の仮判定を見ずに付けたもの（人間に確認済み）。
- 仮判定（題名だけから推測）は、ex-day の目的や #1 の問いの意図を会話で知っている Claude が付けた。本文を読んだサブエージェントより人に近かったのは、この前提の知識の差の可能性がある（基準なし・ありのサブエージェントには、サービスの短い説明と判定の指示だけを渡した）。ただし、前提（サービスの説明と問いごとの意図）を足しても一致は上がらず、かえって厳しく判定する組が増えた（意図が具体的になったぶん、記事に根拠を求めた）。前提の渡し方で結果が変わることはわかったが、何が効くかはこの1回ではわからない。
- 「同じ場所の別の話題」は、人の判断では基本は 1。生麦事件（生麦の食文化が起点）を 2 にしたのは、「生麦でいちばんの出来事」という地域での重みによる個人の判断で、人によって変わりうる（人間に確認済み）。
- 記事は冒頭の最大300字だけを渡している。本文に書いてあることでも、冒頭になければ AI は根拠にできない（例：倉庫が赤れんが造りか、庭園に古い建物があるか）。
- 人の判定を1件直した：帝蚕倉庫（「赤煉瓦の倉庫」の問い）を 2 → 0。人間によると、記事の写真に引っ張られて付けたもので、内容としては関係しない。AI の判定を見たあとの見直しであることに注意。`../accuracy/results/accuracy_ruri-v3-30m_reviewed.md`（#9）はこの修正の前の判定で数えたもので、取り直していない（1件のため、結論は変わらない見込み）。
- 人の判定は1人分。各条件1回だけの実行で、揺れは測っていない。
- 「基準あり」の基準は、#9 の同じ100件を判定した人の考え方から作った。具体例は除いたが、同じデータで評価しているので、効果は高めに出ている可能性がある。
