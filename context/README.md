# 会話の投稿どうしの近さを見る（[ex-day/poc#2](https://github.com/ex-day/poc/issues/2)）

会話を話題（文脈）ごとに分けられないかを考えるための、最初の小さな実験です。短い会話の投稿どうしや、積み重なった会話の文脈と新しい投稿が、どのくらい「近い」と判定されるかを、埋め込み（Ruri v3、e5）で見ます。

Ruri v3 は用途ごとに先頭に付ける言葉が決まっているので、「意味」（なし）と「話題」（`トピック: `）の両方で比べます。

## 題材

[`posts.json`](posts.json) の7つの投稿です（利用イメージで、実在の人物・出来事とは関係ありません）。

| 投稿 | 返信先 | 本文 | 正解の話題 |
|---|---|---|---|
| P1 | － | 桜木町から山下公園まで散歩したよー、天気よかったから気持ちよかった | T1・T2 |
| P2 | P1 | 天気よくてよかったね、海辺だし風はどうだった？ | T1（天気） |
| P3 | P2 | そこまで吹いてなかったよ、まぁでも海近いしビル風もあるしね | T1 |
| P4 | P3 | そうだよね | T1 |
| P5 | P1 | どこあるいたの？ | T2（経路） |
| P6 | P5 | ロープウェイのところ | T2 |
| P7 | P6 | 汽車道か、赤レンガよった？ | T2 |

気になっていること：

- 「そうだよね」や「どこあるいたの？」のような短い投稿は、何かと近くなるのか
- 「汽車道」（場所・道）と「ロープウェイ」（乗り物）は近いと判定されるのか

## 動かし方

```bash
cd context
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python similarity_demo.py                                   # 既定：Ruri v3（30m）
python similarity_demo.py cl-nagoya/ruri-v3-70m intfloat/multilingual-e5-small   # モデルを指定
```

`vector/` の `.venv` があれば、それをそのまま使っても構いません。

## 出るもの

1. 投稿どうしの近さの表（1.00 に近いほど近い）
2. 投稿ごとに、いちばん近いほかの投稿（同じ話題なら ○、違えば ×、どれとも近さが 0 なら －）
3. 積み重なった文脈と比べる：新しい投稿を、それより前の各投稿までの会話の積み重ね（返信先をたどったもの。例：P3 を「P1+P2」と、P6 を「P1+P5」と）と比べ、どの文脈がいちばん近いか。文脈の話題は、その文脈の最後の投稿の話題とする。「返信先の文脈」も並べて表示するので、返信先の文脈がいちばん近くなったかも見られる
4. 単語どうしの近さ（`posts.json` の `words`。汽車道、ロープウェイ、赤レンガ等）

## 埋め込み（Ruri v3・30m）での結果（投稿ごとに比べた場合）

- 同じ話題の投稿がいちばん近かった数は、Ruri（意味）が 5/7 で最もよかった。「天気よくてよかったね、風はどうだった？」と「そこまで吹いてなかったよ」（0.90）のように、単語が一致しなくても天気の話どうしをつなげた
- P6「ロープウェイのところ」と P7「汽車道か、赤レンガよった？」は、お互いにいちばん近かった（0.85）
- P4「そうだよね」と P5「どこあるいたの？」は外れた。中身ではなく、「短い口語の文」という雰囲気どうしで近くなった
- 点数は 0.79〜0.90 の狭い範囲に固まり、差はわずか
- Ruri の「話題」（`トピック: `）は 4/7 で、「意味」より悪かった（7件だけなので決めつけない）
- 単語どうしでは、汽車道は遊歩道（0.88）、ロープウェイは電車（0.89）にいちばん近く、「道」と「乗り物」として見分けているように見える。汽車道とロープウェイは 0.84

## 積み重なった文脈と比べた結果（Ruri v3・30m）

- 「意味」「話題」とも 5/6
- P6「ロープウェイのところ」は、返信先の文脈「P1+P5」（どこあるいたの？）がいちばん近くなった。投稿だけで比べたときは後から来る P7 がいちばん近かったが、問いへの答えとして読むと経路の話になった
- P3・P4・P7 も、返信先の文脈がいちばん近かった。返信先をたどった文脈と、ベクトルでいちばん近い文脈がほぼ一致した
- 外れたのは P5「どこあるいたの？」だけ。どの文脈とも 0.83 前後で横並びで、決め手がなかった。P5 は P1 に返信して、天気とは別の「経路」の話題を始めた投稿で、前のどの文脈にも属さないのが正しいとも言える
- 点数の差はとても小さい（P6 は 0.82 が並び、P7 も 0.84 が並ぶ）。ベクトルは主役ではなく、返信先で決めたことを確かめる役に向きそう

## 1次解析で投稿を話題に振り分ける（Issue [#8](https://github.com/ex-day/poc/issues/8)）

`first_pass.py`：AI を使わない1次解析で、会話の投稿を届いた順に話題へ振り分け、AI に回すべき投稿を数える。#2 の「文脈抽出の最小の形」（返信先で振り分け、ベクトルは確かめ役、話題を始めた投稿は保留）を実装したもの。

| ルール | 内容 |
|---|---|
| 返信先がある | 返信先の話題に入れる。相づち（名詞がなく短い）も同じ。返信先が「保留」なら、まとめて判断する（AI） |
| 分岐の候補 | 返信でも、既存の話題にない名詞が `--branch` 個以上出てきたら、話題が分かれたかもしれないので AI に回す |
| 迷い | ベクトルで、返信先の話題より別の話題が δ 以上近い／返信先がなくベクトルの1位と2位の差が δ 未満 → AI |
| 保留 | 返信先がなく、問いかけ（？・疑問詞・「〜っけ」）か、既存の話題と名詞が重ならない → 保留。返信が来たら判断（AI）。最後まで来なければ AI |

比べるもの：

- 返信先を消す割合（0／0.5／1）。実際の利用者は返信先を付けないことが多いため
- 文脈のベクトル：`concat`（話題の投稿をつなげて1回ベクトルにする）／`mean`（投稿ごとのベクトルの平均）
- 精度は、AI に回した投稿を「ルールの仮の振り分けで扱う（AI なし）」場合と「正解どおりに振り分ける（AI が正しい場合）」の両方を出す

会話のデータ：

- `conversations/sakuragicho_21.json`：桜木町〜山下公園のシナリオ（21件。#2 の途中経過1で作ったもの）。正解の話題、返信先、投稿日つき。P21 は別の日の新しい話（F03 の対象）なので、振り分けからは外す
- `posts.json`：PR #3 の7件
- 会話を増やした分（Claude が書いた架空の会話。場所・歴史は実在。正解の話題は会話を書くときに決めたもので、人がざっと確かめる前提）。会話ごとにねらいを変えた（`_note` に書いた）
  - `kamakura_40.json`：返信の中で話題が分かれる
  - `asakusa_36.json`：返信なしの投稿が、4つの話題で並行して進む
  - `tokyo_station_35.json`：同じ場所の別の話題
  - `takao_36.json`：短い口語のやり取りと、問いと答え
  - `jimbocho_35.json`：日をまたいで話題が戻ってくる、2つの話題にまたがる投稿

```bash
pip install -r requirements.txt   # fugashi・unidic-lite（名詞の取り出し）を追加した
python first_pass.py --env "MacBook Pro（M4 Pro）"            # 既定：Ruri v3 30m
EXDAY_MODEL=ngram-baseline python first_pass.py              # 比較用の基準（文字の重なりだけ）
```

結果は `results/first_pass_<モデル>.md`。最初に全会話の合計（投稿数で重み付け）、次に会話ごと（concat・δ は中央の値）、最後に投稿ごとの振り分けを出す。

精度は、予測の話題を正解の話題に多数決で対応づけて数える。この数え方では、話題を細かく分けすぎても当たりになる。そこで、分けすぎとまとめすぎの両方を数える「まとまりの F」（B-cubed）と、話題の数も出す。

### v2：ベクトルで分岐と新しい話題を見分ける

`first_pass_v2.py`：v1 で分かった2つの弱点を直したもの。

- 返信の中で話題が分かれても、返信先の話題に入ってしまう
- 返信がない投稿が保留になり、AI に回る

ルールは次のとおり（詳しくはファイルの冒頭）。

- 返信がある：返信先の話題とのベクトルの近さが θ_branch 未満なら、分岐の候補として AI に回す
- 返信がない：いちばん近い話題との近さが θ_new 以上なら、その話題に入れる。未満なら、新しい話題を仮に始める。1件のまま終わった仮の話題は AI に回す

しきい値は、正解どおりに振り分けたときの近さの分布から決める。評価する会話を除いた残りの会話で決める（1本抜き）。結果は `results/first_pass_v2_<モデル>.md`。最初に、近さの分布（話題の始まりと続き、分岐と分岐でない返信を、ベクトルで分けられるか）を出す。

```bash
python first_pass_v2.py --env "MacBook Pro（M4 Pro）"
```

### AI にまとめて振り分けさせる

ルールとベクトルでは、話題の切れ目を見分けられなかった。そこで、会話をまとめて AI に渡して振り分けさせる実験をした。[`ai_split/`](ai_split/) を参照。

### 結果のまとめ（#8）

7本（209件）で測った。モデルは Ruri v3 30m。数字は「まとまりの F」（分けすぎ・まとめすぎの両方を数える）。

| 方法 | 返信先あり | 返信先なし（全部消す） | AI に回す割合 |
|---|---|---|---|
| v1：返信先＋ベクトル＋保留（AI なし） | 0.60 | 0.39 | 25%（返信先あり）〜79%（なし） |
| v1：AI に回した投稿が全部正しい場合 | 0.72 | 0.87 | 同上 |
| v2：ベクトルで分岐・新しい話題を判断（AI なし） | 0.45 | 0.38 | 56〜57% |
| AI に会話を一括で渡す（Haiku） | 0.83 | 0.90 | 全件 |
| AI に会話を一括で渡す（Sonnet） | 0.91 | 0.90 | 全件 |

わかったこと：

- 返信先をたどると、返信の中で話題が分かれたこと（脱線）を見落とす。名詞の数で拾うと、AI に回す投稿が5〜8割に増える。
- Ruri のベクトルでは、話題の始まりと続きを見分けられない（AUC 0.41）。分岐した返信と、分岐していない返信も見分けられない（AUC 0.36）。同じ場所の会話では、どの投稿もどの話題とも 0.86〜0.89 の近さになる。ただし、すでにある話題のうちどれに近いかの順位は、72% で正しい。
- 文脈のベクトルの作り方（文章をつなげる／投稿ごとのベクトルを平均する）と δ は、結果にほとんど影響しない。
- AI に会話をまとめて渡すと、返信先がなくても F 0.9 前後になる。ただし、7本のうち6本は会話も正解も Claude が書いたものなので、高めに出ている可能性がある（`ai_split/README.md`）。
