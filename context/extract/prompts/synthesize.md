# 主張をまとめて、わかってきたことと、まだわかっていないことを書く

ex-day は、場所について人が投稿し、返信し合うサービスです。会話の投稿と、そこから取り出した「主張」（発言ごとの1つの主張。根拠の投稿 id 付き）を渡します。主張をまとめて、その場所について「わかってきたこと」と、「まだわかっていないこと」（答えが付けば確かになる問い）を書いてください。

## わかってきたこと

- 主張を、場所や対象ごとに束ねて、その場所について何がわかるかを書きます。1つの主張をそのまま書き写すのではなく、いくつかの主張から言えることを、一段まとめた言い方にします。
  - 例：「A店の隣にB店があった」「B店は高かった」「B店はおいしかった」 → 「この通りには、A店のほかにも飲食店があった」
- 理由や例の関係が会話にあれば、つないで書きます。
  - 例：「花火が見える場所が減った」「C橋は建て替えで見えなくなった」 → 「花火が見える場所が減っている。例として、C橋は建て替えで見えなくなった」
- 会話に書かれていないことは足しません。一般的な知識や、モデル自身の知識で補いません。
- 時期を混ぜません。「まだある」と「昔あった」を、同じ「ある」にまとめません。
- 種類（`kind`）：
  - `事実`：場所・店・道・地名などについて、会話で述べられたこと（見える、ある、なくなった、混む、など）
  - `説`：理由や由来についての見方（「〜だからだという」「〜ではないか」）。説は、事実として言い切らずに書きます
- 次のものは書きません。
  - 人によって受け止めが違う注意や感想（運転の注意、怖い、など）
  - 投稿した人自身についての情報（住んでいるところ、生活など）
  - 相づち、あいさつ、冗談だけのやり取り

## まだわかっていないこと

- わかってきたことのうち、まだ確かでないもの、足りないところがあるものについて、答えが付けば確かになる問いを書きます。
  - 範囲：どこか、どの区間か（「〜の区間がある」が、どこかわからない）
  - 確度：本当か（「〜な気がする」「〜らしい」「〜ではないか」）
  - 理由：なぜか（そうなっている理由がわからない）
  - 条件：誰でも・いつでもそうか
  - 現状：今はどうか（昔の話で、今がわからない）
- 会話の中ですでに出ていて、答えのない問いは、その投稿の id を `question_src` に書き、`in_conversation` を `true` にします。
- 問いがないわかってきたことがあってよいです。無理に作りません。

## 入力

- 会話：投稿の一覧（`id`、`day`、`author`、`reply_to`、`text`）
- 主張：一覧（`id`、`content`、`kind`、`src`）。主張にない情報が会話にあれば、会話から拾ってかまいません（そのときは `posts` に投稿の id を書く）

## 出力

次の形の JSON を、指定されたファイルに書いてください。説明の文章は要りません。

```json
{
  "conversation": "会話の名前",
  "findings": [
    {"id": "W1", "content": "...", "kind": "事実", "claims": ["F2", "F3"], "posts": ["P6", "P7"]}
  ],
  "questions": [
    {"id": "Q1", "about": "W1", "question": "...", "type": "範囲", "in_conversation": false, "question_src": []}
  ]
}
```

- `claims` は、束ねた主張の id。`posts` は、根拠の投稿の id（束ねた主張の `src` と、会話から拾った投稿）。
- `type` は、範囲／確度／理由／条件／現状 のどれか。
