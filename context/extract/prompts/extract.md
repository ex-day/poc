# 会話から知見を取り出す

ex-day は、場所について人が投稿し、返信し合うサービスです。会話の投稿を読んで、あとからその場所を訪れる人や調べる人の役に立つ「知見」を取り出してください。知見ごとに、根拠になった投稿の id を残します。

## 知見とは

- 1つの知見には、1つの主張だけを書きます。2つ以上の主張が入るなら、分けます。
- その文だけを読んで意味が分かるように書きます。「あそこ」「その店」「それ」のような指す言葉は、会話から分かる名前や場所に置き換えます。会話から分からなければ、分からないままにします（地名や店名を推測で足さない）。
- 会話で述べられていないことは書きません。一般的な知識で補いません。
- 複数の投稿を合わせて初めて言える主張は、1つの知見にまとめます（例：「どこを歩いたの？」→「ロープウェイのところ」）。
- 次のものは取り出しません。
  - あいさつ、相づち、冗談だけのやり取り
  - 場所と関係のない雑談
  - 投稿した人自身についての情報（住んでいるところ、生活など）

## 各項目

- `content`：主張。日本語の1文。
- `kind`：次のどれか1つ。
  - `事実`：場所・店・道・地名などについての情報（あった、なくなった、混む、見える、など）
  - `体験`：誰かがその場所でしたこと、見たこと、食べたこと
  - `評価`：良い、高い、怖い、行きにくいなどの感想や意見
  - `疑問`：会話の中で答えが出ていない問い
- `place`：主張の対象の場所。会話に出てきた名前で書く。分からなければ `null`。
- `when`：いつの話か（今、昔、春、夕方など）。会話から分かるときだけ書く。分からなければ `null`。
- `src`：その主張を支える投稿の id。次の投稿を、すべて挙げます。
  - 主張の中身が書かれている投稿
  - 主張を読み取るのに欠かせない投稿（問いに答えた投稿の、問いの側など）

  話のきっかけになっただけの投稿や、相づちは入れません。

## 入力

投稿の一覧（JSON）。各投稿は `id`、`day`（何日目か）、`author`、`reply_to`（返信先の投稿 id。空のこともある）、`text`。

## 出力

次の形の JSON を、指定されたファイルに書いてください。説明の文章は要りません。

```json
{
  "conversation": "会話の名前",
  "facts": [
    {"id": "F1", "content": "...", "kind": "事実", "place": "...", "when": null, "src": ["P4", "P5"]}
  ]
}
```

- `id` は F1, F2, F3… の順に付けます。
- 知見がなければ `"facts": []` にします。
