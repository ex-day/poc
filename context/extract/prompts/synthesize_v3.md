# 主張をまとめて、わかってきたことと、まだわかっていないことを書く（v3）

ex-day は、場所について人が投稿し、返信し合うサービスです。会話が属する場所（`place`。この会話はこの場所についての会話として投稿された）と、会話の投稿と、そこから取り出した「主張」（発言ごとの1つの主張。根拠の投稿 id 付き）を渡します。主張をまとめて、その場所について「わかってきたこと」と、「まだわかっていないこと」（答えが付けば確かになる問い）を書いてください。

## わかってきたこと

- 主張を、場所や対象ごとに束ねて、その場所について何がわかるかを書きます。1つの主張をそのまま書き写すのではなく、いくつかの主張から言えることを、一段まとめた言い方にします。
  - 例：「A店の隣にB店があった」「B店は高かった」「B店はおいしかった」 → 「この通りには、A店のほかにも飲食店があった」
- 理由や例の関係が会話にあれば、つないで書きます。
  - 例：「花火が見える場所が減った」「C橋は建て替えで見えなくなった」 → 「花火が見える場所が減っている。例として、C橋は建て替えで見えなくなった」
- 会話に書かれていないことは足しません。一般的な知識や、モデル自身の知識で補いません。
- 時期を混ぜません。「まだある」と「昔あった」を、同じ「ある」にまとめません。
- 店名がなくても、いくつかの主張から、場所の性格として言えることがあれば書きます（例：「昔ながらの店がまだある」「安い店が多い」 → 「この街には昔からの飲み屋街がある」）。問いにする前に、一段まとめた知見にできないかを見ます。
- 同じ場所に、同じ種類の施設や店が集まっていれば、「集まっている」と書きます（例：「大型の家具店ができた」「ホームセンターもある」 → 「この道沿いには大型の店が集まっている」）。
- 施設や風景が変わったこと（移転した、なくなった、建て替わった、昔は〜だった）は、今昔として書きます。
- 「昔あった」「あったよね」だけで、今もあるかがわからないものは、`status` に「今もあるかは未確認」と書きます。なくなったと言い切りません。
- `place` とは別の場所（近くの街、ほかの地域）についての知見も書き、`related_places` にその場所の名前を書きます。`place` そのもの、または `place` の中の場所なら書きません。
- 会話の中で、同じ場所が別の言い方で呼ばれていたら（略称、地元の呼び方など）、`aliases` にその呼び方を書きます。別名を推測で足したり、問いにしたりはしません。
- 種類（`kind`）：
  - `事実`：場所・店・道・地名などについて、会話で述べられたこと（見える、ある、なくなった、混む、など）
  - `説`：理由や由来についての見方（「〜だからだという」「〜ではないか」）。説は、事実として言い切らずに書きます
  - `価値`：その場所の魅力（景色が綺麗、歴史が感じられる、など）。店の良し悪しは価値にしません
- 次のものは、わかってきたことにも、問いにもしません。会話に書かれていても、主張として取り出されていても、書きません。
  - 危険な情報：立入禁止の場所への入り方、危ない近道や危ない場所での遊び方など。本人だけでなく、その場所の管理者や、何かあったときに対応する人にも迷惑がかかります。「立入禁止である」こと自体は書いてかまいませんが、入り方や「そこはよく釣れる」のような誘いと組み合わせません
  - 店の評価：良い・悪い、安い・高い、おいしい・まずいなど。店については、存在と特徴（何の店か、どこにあるか、何を売っているか、いつからあるか）だけを書きます
  - 私人についての情報：投稿した人、店主、近所の人、事故にあった人など。名前の入った店名や地名（「〇〇の店」「〇〇神社」）は、場所の名前として書いてかまいません。歴史上の人物や記録に残る人は、場所の歴史の一部として書いてかまいません（主語は場所）
  - 公開されると、店や第三者が困るかもしれない情報（店が表に出していない頼みごとを聞いてくれる、など）
  - 会話の中で否定された説
  - 人によって受け止めが違う注意や感想（運転の注意、怖い、など）
  - 相づち、あいさつ、冗談だけのやり取り

## まだわかっていないこと

- わかってきたことのうち、まだ確かでないもの、足りないところがあるものについて、答えが付けば確かになる問いを書きます。
  - 範囲：どこか、どの区間か（「〜の区間がある」が、どこかわからない）
  - 確度：本当か（「〜な気がする」「〜らしい」「〜ではないか」）
  - 理由：なぜか（そうなっている理由がわからない）
  - 条件：誰でも・いつでもそうか
  - 現状：今はどうか（昔の話で、今がわからない）
- 問いは、1つのわかってきたことに1つまでです。答えが付いたときに、そのわかってきたことがいちばん確かになるものを選びます。次は、問いを足す理由ではなく、選ぶときの目安です。
  - 変化の知見（減っている、変わった、なくなった、移った）は、まず「なぜか」（理由）を考えます
  - 指す先があいまいな場所（「飲み屋街」「あのあたり」）は、細かい範囲より先に、どこを指すかを考えます
  - 見え方や混み具合のように、時間帯・季節で変わるものは、条件を考えます
- 会話から読めて、すでにはっきりしていることには、問いを付けません。
- 会話の中ですでに出ていて、答えのない問いは、その投稿の id を `question_src` に書き、`in_conversation` を `true` にします。
- 問いがないわかってきたことがあってよいです。無理に作りません。

## 入力

- 場所：`place`
- 会話：投稿の一覧（`id`、`day`、`author`、`reply_to`、`text`）
- 主張：一覧（`id`、`content`、`kind`、`src`）。主張にない情報が会話にあれば、会話から拾ってかまいません（そのときは `posts` に投稿の id を書く）

## 出力

次の形の JSON を、指定されたファイルに書いてください。説明の文章は要りません。

```json
{
  "conversation": "会話の名前",
  "findings": [
    {"id": "W1", "content": "...", "kind": "事実", "status": null, "related_places": [], "aliases": [], "claims": ["F2", "F3"], "posts": ["P6", "P7"]}
  ],
  "questions": [
    {"id": "Q1", "about": "W1", "question": "...", "type": "範囲", "in_conversation": false, "question_src": []}
  ]
}
```

- `claims` は、束ねた主張の id。`posts` は、根拠の投稿の id（束ねた主張の `src` と、会話から拾った投稿）。
- `status` は、今もそうかがわからないときだけ書きます（それ以外は `null`）。`related_places` は、`place` とは別の場所の知見のときだけ書きます。`aliases` は、会話の中で別の呼び方が出たときだけ書きます。
- `kind` は、事実／説／価値 のどれか。
- `type` は、範囲／確度／理由／条件／現状 のどれか。
