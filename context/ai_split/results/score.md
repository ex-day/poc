# AI にまとめて振り分けさせた結果（Issue #8・#14）

- 判定役：正解を見せないエージェント（Claude Code のサブエージェント、Codex）。条件の名前に、提供元・モデル・呼び方が入る
- 呼び方に -seq10 が付かないものは、会話の全投稿を一度に渡す（一括）。-seq10 は、10件ずつ順に渡し、前までの振り分けを変えずに引き継ぐ（`seq_run.py`）。返信先なしは、reply_to を全部消した入力
- 精度・まとまりの F・話題の数の意味は `../first_pass.py` の結果と同じ。比べるときは、まとまりの F を主に見る
- 条件の名前：提供元-モデル・呼び方（subagent／codex／api。順に渡す条件は -seq10 を付ける）・指示・返信先。指示は、対象＝`prompts/split.md`（同じ対象を話題にする）、流れ＝`prompts/split_flow.md`（会話の流れのひとまとまりを話題にする）
- 正解が複数ある投稿（「T3 でも可」など）は、どれに振り分けても当たり
- 適合が低い＝別々の話題を混ぜた（重い外れ。あとから分け直せない）。再現が低い＝1つの話題を細かく分けた（軽い外れ。束ねれば戻せる）
- 厳しい F：正解を先頭の話題だけにして数えたまとまりの F（「でも可」の話題は当たりにしない）。「でも可」をどちらも当たりにすると、話題をまとめる側が有利になるため、モデルを比べるときに並べて見る
- 細分を許す F：AI の話題を、多数決で対応づけた正解の話題ごとに束ねてから数えたもの。細かく分けただけなら下がらず、混ぜると下がる
- 人が書いた会話：kohoku_31、tsurumi_38、posts。それ以外は Claude が書いた会話
